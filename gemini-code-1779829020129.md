# System Blueprint & Build Instructions: EU Public Affairs & Competition Intelligence Platform for Enel

## 1. Project Overview & Objective
You are tasked with building a production-ready, AI-powered Web Application designed for Enel’s Brussels public affairs team. This team manages Enel's strategic engagement with the European Commission, European Parliament, and key regulatory agencies (specifically focusing on DG COMP, DG ENER, and ACER). 

The platform must act as an automated intelligence hub that monitors legislative movements, parses public consultations, extracts judicial case law precedents, maps out stakeholder networks, and compiles real-time market data into high-impact executive summaries.

---

## 2. Technical Stack
*   **Frontend**: React (TypeScript) + Vite + Tailwind CSS + Lucide React (for clean utility/corporate dashboards).
*   **Backend**: Python (FastAPI) to handle high-performance async tasks, data extraction, and API orchestration.
*   **Vector Database**: Qdrant or pgvector (PostgreSQL) for storing multi-lingual policy embeddings.
*   **AI/LLM Engine**: Gemini 1.5 Pro or Flash via Google Gen AI API (utilized for heavy multi-document summaries, structural code translation, and entity mapping).
*   **Orchestration / Pipelines**: LangChain or LlamaIndex + Celery (for scheduling asynchronous scrapers and API polling).

---

## 3. Data Ingestion & API Integration Specifications
You must establish pipelines to connect, fetch, and structure data from the following authoritative EU sources:

### 3.1. EUR-Lex (Semantic Cellar Database)
*   **Purpose**: Track and analyze binding EU regulations, directives, and preparatory acts.
*   **Access Protocol**:
    *   Primary access must bypass the basic EUR-Lex web interface by querying the public SPARQL endpoint of the EU Publications Office (Cellar semantic database).
    *   **SPARQL Endpoint URL**: `http://publications.europa.eu/webapi/rdf/sparql`.
    *   **Retrieval Mechanism**: Use Python's `SPARQLWrapper` or reference the logic of the `eurlex` implementation pattern. Query Cellar to retrieve legislative identifiers (`CELEX` codes) and corresponding legal metadata.
    *   **Document Fetching**: Perform GET requests to the Cellar REST API using the retrieved unique Cellar URIs or CELEX numbers to download the full legal text in XML/HTML formats.

### 3.2. European Parliament Open Data Portal API (v2)
*   **Purpose**: Monitor parliamentary questions, committee agendas, voting records, and MEP profiles.
*   **Access Protocol**:
    *   **API Base URL**: `https://data.europarl.europa.eu/api/v2`.
    *   **Key Endpoints to Implement**:
        *   `GET /parliamentary-questions` (Track MEP questions targeting State aid, Enel's 3SUN factory, or energy grid fees).
        *   `GET /parliamentary-questions/feed` (Poll weekly for updated legislative inquiries).
        *   `GET /meetings/{sitting-id}/vote-results` (Track plenary votes and committee-level splits).
        *   `GET /documents/feed` (Fetch newly updated EP committee draft reports and resolutions).

### 3.3. European Commission "Have Your Say" Portal
*   **Purpose**: Capture industry and NGO feedback on early-stage Commission proposals.
*   **Access Protocol**:
    *   Implement an asynchronous python task modeled on the `hys_scraper` programmatic utility.
    *   **Extraction Pipeline**: Given a target publication ID (PID):
        1. Fetch feedback submissions via the portal's underlying JSON endpoints.
        2. Downstream download of attached stakeholder PDFs (e.g., position papers from trade groups or environmental associations).
        3. Parse the data into relational tables storing country demographics, sector categories, and feedback text.
